# ATV Remote — an Apple TV remote in the macOS menu bar

**English** · [Русский](README.ru.md)

[![Release](https://img.shields.io/github/v/release/kidwhoseeghosts/atv-remote-mac)](https://github.com/kidwhoseeghosts/atv-remote-mac/releases)
[![Build](https://github.com/kidwhoseeghosts/atv-remote-mac/actions/workflows/build.yml/badge.svg)](https://github.com/kidwhoseeghosts/atv-remote-mac/actions/workflows/build.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![macOS 14+](https://img.shields.io/badge/macOS-14%2B-lightgrey)

ATV Remote lives in the menu bar (no Dock icon) and controls your Apple TV over the local network.
The UI mimics the Apple TV Remote in iPhone's Control Center: a large touch surface, round buttons, a "Now Playing"
card with artwork, glass styling (Liquid Glass on macOS 26+, `.ultraThinMaterial` on older systems), spring animations
and trackpad haptics.

* UI: Swift / SwiftUI, macOS 14+, universal binary (Apple Silicon and Intel).
* Protocols: [pyatv](https://pyatv.dev) 0.18.0 running as a long-lived Python service (`Resources/python/atvd.py`), talking JSON Lines over stdin/stdout.
* No paid developer account needed: ad-hoc signed, sandbox off.
* Localized in English and Russian — follows the system language.

## Features

| | |
|---|---|
| Device picker | a "pill" at the top, mDNS discovery, remembers the last device |
| Clickpad | swipe with mouse/trackpad or two-finger scroll → arrows; click → Select; direction highlight; optional edge-click arrows |
| Buttons | Back (Menu), Home (TV), Play/Pause, Mute, Volume ± (auto-repeat), ±10 s skip, Power |
| Now Playing | title, subtitle, artwork, progress |
| Apps | Apple TV app grid (`app_list`) with search and launch (`launch_app`) |
| Text input | `keyboard.text_set` — when a text field is active on the Apple TV |
| Pairing | PIN for Companion, AirPlay and MRP; keys are stored in `~/Library/Application Support/ATVRemote/pyatv.conf`, reconnects automatically |
| Hotkeys | global (Carbon `RegisterEventHotKey`), configurable, with conflict warnings; arrows/Return/Space/⌫/H/+/−/,/. also work when the remote window is focused |
| Floating window | a separate window with the same remote and an "always on top" pin (📌) |
| Volume diagnostics | shows active protocols, runs every volume method one by one, lets you pick the one that works (see [Volume diagnostics](#volume-diagnostics)) |
| Localization | English and Russian (String Catalog); follows the system language |
| Launch at login | `SMAppService.mainApp` (toggle in Settings) |
| Dark/light, VoiceOver | labels and actions on every element |

## Requirements

* macOS 14 (Sonoma) or newer — Apple Silicon or Intel (universal build).
* An Apple TV (tvOS) on the same network as the Mac.
* Python 3.9+ (Homebrew or the Command Line Tools one) — used on first launch to install pyatv into a private venv.

## Install from a Release

1. Download `ATVRemote-<version>.zip` from the [Releases](https://github.com/kidwhoseeghosts/atv-remote-mac/releases) page and unzip it.
2. Move `ATVRemote.app` to `/Applications`.
3. The app is ad-hoc signed (no paid developer account), so macOS quarantines the downloaded copy. Remove the quarantine flag:

   ```bash
   xattr -dr com.apple.quarantine /Applications/ATVRemote.app
   ```

   (or right-click the app → **Open** → **Open**).
4. Launch it — the icon appears in the menu bar. On first launch it offers to install pyatv (see below).

### Local Network access

On the first scan macOS asks whether ATVRemote may find devices on the local network — **allow it**.
If you declined: System Settings → Privacy & Security → Local Network → enable ATVRemote.

## Build from source

You need Xcode 16+ (any version that builds for macOS 14+) and [Homebrew](https://brew.sh).
`project.yml` is the source of truth; `ATVRemote.xcodeproj` and `Config/Info.plist` are generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) and are not checked in.

```bash
git clone https://github.com/kidwhoseeghosts/atv-remote-mac.git
cd atv-remote-mac
brew install xcodegen
xcodegen && open ATVRemote.xcodeproj
```

In Xcode: target **ATVRemote → Signing & Capabilities** — keep "Sign to Run Locally" (ad-hoc) or pick your Personal Team. Press ⌘R.

From the terminal (build + install to /Applications + launch):

```bash
scripts/build.sh --install --open
```

Release build (universal, ad-hoc signed) and archive:

```bash
scripts/release.sh               # → dist/ATVRemote-<version>.zip (+ .sha256); reveals the .app in Finder
UNIVERSAL=0 scripts/release.sh   # host architecture only (faster)
scripts/release.sh --no-open     # don't open Finder
```

## First launch: installing pyatv

On first launch the app shows a "First-time setup" screen. The **Install pyatv** button:

1. finds Python 3.9+ (Homebrew first, then `/usr/bin/python3` from the Command Line Tools);
2. creates a venv in `~/Library/Application Support/ATVRemote/venv`;
3. installs `pyatv==0.18.0` and `srptools<2` (from `Resources/python/requirements.txt`) with a progress bar and a log.

> **About `srptools`.** `srptools` 2.0.0 breaks pyatv pairing, so it is pinned to `<2`.
> If you install by hand, use `requirements.txt` rather than a plain `pip install pyatv`.

No Python? `xcode-select --install` or `brew install python`. The same can be done manually with `scripts/setup_venv.sh`.

## Pairing

1. In the device list press **Pair** (or pick an unpaired device in the pill).
2. The app asks for a PIN for each needed protocol in turn: **Companion** (keys, apps, power, text input),
   then **AirPlay** (artwork, metadata, volume) and, if needed, **MRP** (old Apple TVs / tvOS ≤ 14).
3. A 4-digit PIN appears on the TV — enter it in the app.
4. You can skip a protocol; the matching features will then be unavailable (buttons are dimmed).

To forget a device: the device row's context menu or "Settings → Forget device".

## Hotkeys

Default modifier is **⌃⌥**:

| Action | Shortcut | | Action | Shortcut |
|---|---|---|---|---|
| Up/Down/Left/Right | ⌃⌥ + arrows | | Volume up / down | ⌃⌥ = / ⌃⌥ − |
| Select | ⌃⌥ ↩ | | Mute | ⌃⌥ M |
| Back (Menu) | ⌃⌥ ⌫ | | Power | ⌃⌥ P |
| Home (TV) | ⌃⌥ H | | Play/Pause | ⌃⌥ Space |
| Skip ±10 s | ⌃⌥ , / ⌃⌥ . | | Floating window | ⌃⌥ R |

Arrows, volume and skip repeat while held.

**Conflict with Rectangle.** Rectangle claims **⌃⌥ + arrows**, **⌃⌥ Return** and others by default. If a shortcut is already taken,
macOS refuses the registration: a ⚠ appears next to it in Settings → Global shortcuts together with a warning. Change the shortcut
in the app (click it → press the new one; Esc cancels) or disable the conflicting one in Rectangle. ⌃⌥⇧ + arrows are usually free.
Global shortcuts do not require the Accessibility permission.

## Floating window

"⋯" → "Floating remote window" (or ⌃⌥R). Drag it by the background; it remembers its position.
The 📌 button toggles "always on top". Keyboard shortcuts work while the window is focused.

## Launch at login

Settings → "Launch at login". More reliable when the app is in `/Applications`. If the status says "approval required", allow it in
System Settings → General → Login Items. With ad-hoc signing macOS may refuse — this is a system limitation; add the app to Login Items manually.

## Demo mode (no Apple TV)

`/Applications/ATVRemote.app/Contents/MacOS/ATVRemote --demo`, or the "Demo mode" switch in Settings (then restart the service).
A virtual device "Living Room (demo)" appears; the pairing PIN is **1234**. Handy for looking around and trying pairing.
The service can also run on its own: `scripts/run_daemon_demo.sh`.

## Volume

**Volume ±** tries several channels in order until one works (the method chosen in diagnostics goes first):

1. **MRP HID over the AirPlay tunnel** — how the Remote in iPhone's Control Center controls volume (needs AirPlay pairing);
2. **Companion HID** (VolumeUp/VolumeDown, codes 8/9);
3. pyatv `remote_control.volume_up/down`;
4. `audio.volume_up/down` (AirPlay speakers and HomePod);
5. AirPlay `set_volume` (absolute level, ±5 %).

"Hold" variants (Companion/MRP: 0.4 s press) are not part of the automatic order — only of diagnostics.

### Volume troubleshooting

What actually works depends on the Apple TV setting
**Settings → Remotes and Devices → Volume Control**:

* **HDMI-CEC / Auto** (or a HomePod/AirPlay speaker) — volume ± works over the network, but the level is not reported (always "0"); that's normal.
  Enable HDMI-CEC on the TV (Samsung: Anynet+, LG: SimpLink, Sony: Bravia Sync …). If CEC volume is flaky on tvOS 26.2, re-select
  "Volume Control" (e.g. "Auto" → your TV again).
* **IR** (infrared sent by the Apple TV box itself) — volume **cannot** be changed over the network, neither from this app nor from the
  iPhone Remote. Note that a physical Siri Remote often controls the TV **directly over IR**, so the fact that it changes volume doesn't prove
  CEC through Apple TV works — the iPhone remote does.

The service log shows which path was used: `Volume: volume_up sent via …`; on connect it also writes a summary
`Volume: protocols=…; mrp_tunnel=yes/no; …` (the service log is always in English).

### Volume diagnostics

**Settings → Volume → Volume diagnostics**:

1. The screen shows the active protocols, whether the AirPlay MRP tunnel is up and whether AirPlay is paired.
   If AirPlay isn't paired, use **Pair AirPlay** (the PIN appears on the TV). If it is paired but the tunnel isn't up, turn on
   **Force MRP tunnel** (reconnects).
2. **Run test** tries every method in turn: volume up → 2 s pause → volume down → 2 s pause. Watch the TV screen.
3. In the results press **Volume changed — choose this** for the method that worked: it is remembered and tried first. "Automatic" resets the choice.
4. If nothing helps, send `~/Library/Application Support/ATVRemote/daemon.log`: it records the result for every method
   ("Volume diagnostics …" lines) and the protocol summary.

### Other notes

* **Mute** is best-effort: Companion has no Mute button. It only works when the Apple TV controls the output volume itself
  (HomePod/AirPlay speaker): 0 ↔ previous level. On a TV with HDMI-CEC the button stays active but shows an explanation — use Volume Down or the TV remote.
* Artwork and metadata come over AirPlay/MRP — without those pairings the card stays empty.
* Text input only works while a text field is active on the Apple TV.
* The clickpad sends discrete arrows (like the physical ring), not smooth scrolling — a Companion limitation.

## Troubleshooting

* Service log: `~/Library/Application Support/ATVRemote/daemon.log` ("Settings → Show log").
* Devices not found: are the Mac and the Apple TV on the same network/VLAN? Is Local Network access allowed? Is a VPN off?
* pyatv won't install: check the log on the setup screen; you can run `scripts/setup_venv.sh` in a terminal.
  On Python 3.14 some dependencies lack prebuilt wheels — the app prefers 3.13…3.10.
* Pairing "failed": press Retry; the PIN is short-lived. Make sure `srptools` is 1.x
  (`~/Library/Application Support/ATVRemote/venv/bin/pip show srptools`).
* Service crashed: the app restarts it up to 3 times; then "Settings → Reinstall environment".
* Reset: delete `~/Library/Application Support/ATVRemote` (wipes keys and venv) and run `defaults delete local.atvremote.ATVRemote`.

## Localization

The UI is available in **English** (development language) and **Russian** and follows the system language (English for anything else).
Strings live in `Resources/Localizable.xcstrings` (String Catalog) and `Resources/InfoPlist.xcstrings`; keys in code are the English phrases.
User-facing messages from the Python service are translated by the service itself: the app passes the language with `--lang`
(the `RU` dictionary in `atvd.py`); the log is always English. To add a language: add it to `knownRegions` and `CFBundleLocalizations`
in `project.yml`, translate both catalogs and the dictionary in `atvd.py` (the `LocalizationTest` unit test checks that every service message is translated).

## Icon

The app icon (macOS 26 style: squircle, dark glass gradient, a MacBook with the Siri Remote on its screen) and the monochrome template
menu-bar icons (outline = disconnected, filled = connected) are drawn in code:
`pip install pillow numpy && python3 scripts/make_icon.py` (optionally `--preview docs/icon-preview.png`).
The output lives in `Resources/Assets.xcassets`, wired via `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` in `project.yml`.
After changing `project.yml` run `xcodegen generate`.

### Service protocol (JSON Lines)

Request: `{"id":7,"cmd":"key","key":"up","action":"tap"}` → response `{"type":"response","id":7,"ok":true,"result":{}}`
or `{"ok":false,"error":{"code":"not_supported","message":"…"}}`.
Events: `{"type":"event","event":"playing","data":{…}}` (`state`, `playing`, `artwork`, `power`, `features`, `keyboard`, `volume`, `volume_diag`, `log`, `ready`).
Commands: `hello, quit, set_options, scan, pair_start, pair_pin, pair_cancel, forget, connect, disconnect, key, power, apps, launch_app, text, set_volume, mute, volume_diag, now_playing, status`.
`set_options` accepts `artwork`, `client_name`, `volume_method` (`auto|mrp_hid|companion_hid|remote_control|audio|set_volume`), `force_mrp_tunnel`.
`volume_diag`: no arguments — channel state and the list of methods; `{method, direction}` — one method; `{run:true, delay:2}` — full run with `volume_diag` events.
The app also passes `--lang <code>` when starting the service (user-facing messages are returned in that language).

## Tests

```bash
tests/run-checks.sh      # service unit tests, integration with real pyatv, Swift layer typecheck, client end-to-end test
```

Works on macOS and Linux (on Linux the `tests/linux-shim` shim is added). Variables: `VENV=path` (a venv with pyatv),
`PYATV_SRC=path` (pyatv sources for the integration test). The same Python tests and the build run in GitHub Actions.

## What has been verified

* Volume, pairing and control are **verified on a real Mac and Apple TV** (volume works with Volume Control = HDMI-CEC/Auto).
* On Linux (CI-style checks): the `atvd.py` service — unit tests against a fake device and an integration test with real pyatv 0.18.0;
  the Swift `Core/` + `RemoteController` layer compiles and `DaemonClient` passes an end-to-end test with the real service in demo mode.
* The string catalogs and the UI layer are not compiled on Linux — Xcode builds them.

## Releasing (maintainers)

1. Bump `MARKETING_VERSION` in `project.yml` and add a `CHANGELOG.md` entry.
2. `scripts/release.sh` — local check of the build and archive.
3. `git tag vX.Y.Z && git push origin vX.Y.Z` — GitHub Actions builds the archive and attaches it to a GitHub Release.
